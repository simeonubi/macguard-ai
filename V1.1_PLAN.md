## 1. Executive Summary

MacGuard AI v1.0.0 established a hardened, safety-first storage cleanup engine for macOS with 255 passing unique automated tests, zero permanent deletion primitives, and cryptographic HMAC-SHA256 human approval workflows. 

MacGuard AI v1.1 evolves the product from a safe cleanup assistant into a **comprehensive, safety-first macOS Storage Intelligence Platform**. The core focus of v1.1 is to **analyze more broadly, categorize more intelligently, explain findings better, and prioritize actionable insights**, while **strictly preserving the frozen v1.0 security boundary**.

The fundamental architectural axioms of v1.1 are:
$$\begin{aligned}
\text{DISCOVERY} &\neq \text{AUTHORIZATION} \\
\text{ANALYSIS} &\neq \text{RECOMMENDATION} \\
\text{RECOMMENDATION} &\neq \text{APPROVAL} \\
\text{APPROVAL} &\neq \text{EXECUTION} \\
\text{AI INTELLIGENCE} &\neq \text{SYSTEM AUTHORITY}
\end{aligned}$$

### B. Current Component Architecture
* **Scanner**: `StorageScanner` performs read-only top-directory and large-file discovery via bounded heaps (`heapq`).
* **Analyzer**: `StorageAnalyzer` evaluates items into 5 categories (`CACHE`, `LOGS`, `DEVELOPMENT`, `DOCUMENTS`, `UNKNOWN`) and 4 risk levels (`LOW`, `MEDIUM`, `HIGH`, `UNKNOWN`).
* **Recommendation**: `RecommendationEngine` generates structured `StorageRecommendation` models with size thresholding and hierarchical parent-child deduplication.
* **Safety & Approval**: `PathValidator` enforces allowlist roots (`~/Library/Caches`, `~/Library/Logs`, `~/.cache`, `DerivedData`) and system denylists. `ApprovalService` generates and verifies 15-minute HMAC-SHA256 tokens using a 256-bit runtime key (`ApprovalKeyManager`).
* **Execution**: `ExecutionPlanner`, `DryRunExecutor`, and `TrashExecutor` manage verified moves exclusively to `~/.Trash`.
* **Integrity**: `PathIntegrity` captures `os.lstat` snapshots and post-move byte-exact SHA-256 checksums.
* **Audit**: `AuditRepository` records structured JSON event logs in a thread-safe SQLite WAL database.
* **Agent & LLM**: `MacGuardAgent` provides conversational reasoning with read-only tools; `ExplanationService` connects to local Ollama with automatic fallback to deterministic rationales (`explain_candidate_safe`).

## 3. v1.1 Primary Goals

1. **Broaden Read-Only Storage Intelligence**: Safely discover and map storage across the bounded user home directory, developer environments, application data, model caches, and system mount points without risk of data mutation.
2. **Deterministic Smart Categorization Registry**: Expand semantic classifications into an extensible category registry with explicit confidence metrics and false-positive boundaries.
3. **Specialized Developer Storage Analyzer**: Provide deep diagnostic intelligence for Xcode, Docker, virtual environments, package managers (npm, pip, conda, cargo, brew), and local AI/ML model caches (Hugging Face, Ollama, PyTorch).
4. **Historical Storage Trends & Growth Analytics**: Utilize SQLite storage snapshots to track directory growth over time, category velocity, and historical space reclaimed.
5. **Read-Only Duplicate & Redundancy Intelligence**: Identify exact file duplicates and redundant archives using two-stage partial/full hashing without loading large files into memory.
6. **Enhanced Advisory Agentic Reasoning**: Enable the AI agent to summarize trends, compare scan snapshots, and explain storage growth while maintaining **zero mutation authority**.

---

## 4. Non-Goals (Strictly Forbidden in v1.1)

1. **NO Autonomous Cleanup Authority**: The AI agent will not gain execution, approval, or deletion capabilities under any circumstance.
2. **NO Whole-Disk Automated Cleanup**: Expanding read-only analysis scope to `Documents`, `Desktop`, `Downloads`, or `Applications` **DOES NOT** make those locations cleanup-eligible. They remain permanently blocked from automated cleanup.
3. **NO Permanent Deletion Primitives**: The system will never introduce `os.remove`, `os.unlink`, `shutil.rmtree`, or shell `rm`.
4. **NO Cloud Telemetry or Cloud LLM Dependency**: All analysis and inference remain 100% local on-device.
5. **NO Unbounded Filesystem Loading**: Traversal will strictly stream metadata through bounded memory structures.
6. **NO Modification to v1.0 Security Engine**: The HMAC-SHA256 signing, one-time token claim, and `TrashExecutor` logic remain frozen.
7. **NO Automatic Duplicate Deletion**: Duplicate intelligence in v1.1 is strictly **Analysis Only**.

```text
    ↓
ANALYSIS (Size, Age, Physical Allocation)
    ↓
DETERMINISTIC CLASSIFICATION (Category Registry & Confidence)
    ↓
RECOMMENDATION (Multi-Factor Priority Scoring)
    ↓
HUMAN APPROVAL (Explicit Review Gate)
    ↓
PATH VALIDATION (Strict Allowlist Enforcement: PathValidator)
    ↓
DRY RUN (Execution Planner Pre-Simulation)
    ↓
CONTROLLED TRASH EXECUTION (Atomic Move to ~/.Trash via Inode Check)
    ↓
INTEGRITY VERIFICATION (Pre/Post Move SHA-256 Checksum)
    ↓
AUDIT (Immutable SQLite Event Store)
```

Separately and in parallel:

```text
LLM / LOCAL AGENT
    ↓
READ-ONLY INFORMATION + NATURAL LANGUAGE EXPLANATION
    ↓
[ NO ACCESS TO HMAC SECRET / NO EXECUTION PRIMITIVES / ZERO SYSTEM AUTHORITY ]
```

## 7. Bounded Scan Scope Architecture (Discovery Boundary)

### A. Principle of Discovery Boundary
> [!IMPORTANT]
> **Discovery is broader than mutation authority, but discovery itself remains explicitly scoped, bounded, permission-aware, and privacy-controlled.**
>
> The v1.1 scanner does NOT possess unrestricted read access to the entire Mac. Discovery is strictly bounded by explicit scope roots, maximum depth caps, resource constraints, filesystem boundaries, and sensitive directory exclusions.

The architecture strictly distinguishes:
1. **READ SCOPE**: The bounded subset of directories configured for discovery and analysis.
2. **CLEANUP ALLOWLIST**: The immutable whitelist of paths eligible for controlled Trash execution (`~/Library/Caches`, `~/Library/Logs`, `~/.cache`, `DerivedData`).
3. **PROTECTED PATHS**: Explicitly blocked roots (system files, user documents, desktop, credentials, keys).

### B. Configurable Scan Scopes
```python
class ScanScope(str, Enum):
    USER_CACHES = "USER_CACHES"          # ~/Library/Caches, ~/Library/Logs, ~/.cache
    DEVELOPER_WORKSPACES = "DEVELOPER"  # ~/Projects, ~/.cargo, ~/.npm, ~/.cache, Xcode
    USER_HOME_BOUNDED = "USER_HOME"      # Bounded ~, excluding sensitive directories
    CUSTOM_SCOPED = "CUSTOM_SCOPED"      # Explicitly user-provided directory path
```

### C. Discovery Traversal Constraints & Boundaries
1. **Depth Limits**: Default maximum recursion depth of 8 levels (configurable up to 12).
2. **Entry Limits**: Maximum of 250,000 filesystem entries processed per scan to prevent memory pressure.
3. **Scan Timeout**: 60-second default timeout per scan root; cooperative cancellation via `threading.Event`.
4. **Permission Failure Resilience**: Inaccessible directories (`EACCES`, `EPERM` e.g., TCC protected folders like `~/Library/Application Support/AddressBook`, `~/Library/Safari`) are caught cleanly, logged as `PERMISSION_DENIED`, and do not halt the scan.
5. **Sensitive Directory Exclusions**: Hard-coded discovery exclusion list:
   - Credentials & Keys: `~/.ssh`, `~/.gnupg`, `~/.aws`, `~/.config/gcloud`, `~/Library/Keychains`
   - Private Personal Data: `~/Library/Mail`, `~/Library/Messages`, `~/Library/Safari`, `~/Library/Cookies`, `~/Library/IdentityServices`, `~/Library/Accounts`
   - Cloud Sync Metadata: `~/Library/Mobile Documents` (iCloud internal sync state)
6. **Symlink Boundary Isolation**: Uses `os.scandir()` and `os.lstat()`. Symlinks pointing outside the current scan scope or pointing to system roots are resolved and never recursively followed. Circular symlinks are detected via `(st_dev, st_ino)` tracking.
7. **Filesystem Boundaries**: Scanner checks `st_dev` on directory entries to prevent crossing into separate physical volumes, external drives, or network mounts unless explicitly targeted.
8. **Hardlink Deduplication**: Files sharing physical inodes (`st_ino`, `st_dev`) on APFS volumes are counted once for physical storage allocation to prevent inflated metrics.

### Deterministic Detection Rules
* **Confidence Scoring**: Each classification calculates a deterministic confidence score ($0.0 - 1.0$) based on:
  1. *Directory Ancestry Match* (Weight: 0.5)
  2. *File Extension Match* (Weight: 0.3)
  3. *Manifest Co-location* (e.g., presence of `pyproject.toml`, `package.json`, `Cargo.toml`) (Weight: 0.2)
* **Unknown Handling**: Any item with confidence $< 0.60$ or matching conflicting rules is assigned `StorageCategory.UNKNOWN` with `RiskLevel.UNKNOWN` and permanently blocked from cleanup.

## 9. Storage Intelligence & Deterministic Scoring Engine

### A. Core Diagnostic Questions Answered
1. **Space Concentration**: What top 5 directories account for $>50\%$ of analyzed space?
2. **Growth Velocity**: Which directories grew by $>20\%$ since the previous recorded scan?
3. **Reclaimable Potential**: What is the exact breakdown between *Eligible Space*, *Manual Review Space*, and *Protected Space*?
4. **Hierarchical Containment**: What parent directories contain nested actionable candidates?

### B. Action Priority Scoring Algorithm ($S_{\text{priority}}$)
$$\text{Score} = \left( \frac{\text{Size}}{\text{Max Size}} \times 0.40 \right) + (\text{Eligibility Weight} \times 0.30) + (\text{Age Days} > 30 \times 0.15) + (\text{Confidence} \times 0.15)$$

* $\text{Eligibility Weight}$: `ELIGIBLE_FOR_REVIEW` = $1.0$, `MANUAL_REVIEW` = $0.5$, `BLOCKED` = $0.0$.
* Scoring is strictly deterministic and provides transparent sorting for user review.

## 10. Storage History & Trends (SQLite Analytics Engine)

### A. Database Schema Extension (v2)
MacGuard v1.1 adds three analytical tables to the existing SQLite database without modifying the immutable security audit schema:

```sql
PRAGMA foreign_keys = ON;

-- 1. Scan Snapshots Table
CREATE TABLE IF NOT EXISTS scan_snapshots (
    snapshot_id TEXT PRIMARY KEY,
    timestamp DATETIME NOT NULL,
    scan_scope TEXT NOT NULL,
    root_path TEXT NOT NULL,
    total_items INTEGER NOT NULL,
    total_bytes INTEGER NOT NULL,
    free_bytes INTEGER NOT NULL,
    metadata_json TEXT
);

-- 2. Category Metrics History Table (Aggregated totals only, NO file paths)
CREATE TABLE IF NOT EXISTS category_history (
    snapshot_id TEXT NOT NULL,
    category TEXT NOT NULL,
    item_count INTEGER NOT NULL,
    total_bytes INTEGER NOT NULL,
    PRIMARY KEY (snapshot_id, category),
    FOREIGN KEY (snapshot_id) REFERENCES scan_snapshots(snapshot_id) ON DELETE CASCADE
);

-- 3. Top Storage Consumers History Table (Top 25 consumers, paths aliased to ~/)
CREATE TABLE IF NOT EXISTS top_consumer_snapshots (
    snapshot_id TEXT NOT NULL,
    canonical_path TEXT NOT NULL,
    category TEXT NOT NULL,
    size_bytes INTEGER NOT NULL,
    item_type TEXT NOT NULL,
    PRIMARY KEY (snapshot_id, canonical_path),
    FOREIGN KEY (snapshot_id) REFERENCES scan_snapshots(snapshot_id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_scan_snapshots_timestamp ON scan_snapshots(timestamp);
CREATE INDEX IF NOT EXISTS idx_category_history_category ON category_history(category);
CREATE INDEX IF NOT EXISTS idx_top_consumer_snapshot ON top_consumer_snapshots(snapshot_id);
```

### B. Privacy, Retention & Migration Policies
* **Schema Versioning**: Managed via `PRAGMA user_version = 2`. Migrations execute inside an atomic SQLite transaction.
* **Privacy Controls**: `category_history` stores strictly aggregated numbers. `top_consumer_snapshots` limits records to the top 25 largest consumers per scan and stores home-aliased paths (e.g. `~/Library/Caches/...`) rather than absolute raw system paths.
* **Retention Policy**: Automatic rolling purge maintains the most recent 50 scan snapshots or 90 days of history, deleting associated cascade records.
* **Point-in-Time Semantics**: Snapshots represent immutable historical observations; moved/deleted files on disk do not mutate historical records.

## 12. Read-Only Duplicate & Redundancy Intelligence

### A. Two-Stage Streaming Duplicate Detection (ANALYSIS ONLY)
> [!IMPORTANT]
> Duplicate detection in v1.1 is strictly **ANALYSIS ONLY**. MacGuard will never automatically delete or deduplicate files.

```text
Step 1: Size Pre-Filtering (Group files with identical byte sizes >= 1MB)
                 │
                 ▼ (Only evaluate sizes containing >= 2 distinct files)
Step 2: Metadata & Hardlink Pre-Filter (Skip matching (st_dev, st_ino) hardlinks)
                 │
                 ▼
Step 3: Partial Hash Stream (Compute SHA-256 of first 4KB + last 4KB)
                 │
                 ▼ (Only evaluate candidates with identical partial hashes)
Step 4: Full SHA-256 Hash Stream (Chunked 64KB read to confirm exact duplicate)
                 │
                 ▼
Result: Structured DuplicateCluster (Analysis-Only finding; Zero auto-delete)
```

### B. Safety & Performance Bounds
* **Analysis-Only**: Duplicate clusters are presented as informational findings with side-by-side path comparisons.
* **Hardlink & Symlink Handling**: Files sharing the same inode on APFS are recognized as hardlinks (zero wasted physical space). Symlinks are excluded from duplicate hashing.
* **Resource Bounds**: Files $> 5 \text{ GB}$ are excluded from automatic bulk hashing and require explicit user-initiated inspection. All hashing is performed via streaming in-memory buffers with zero temporary file creation and zero network egress.

### A. Agent Capabilities (Strictly Read-Only)

### B. Security Boundaries (Zero Authority)
* The agent cannot create, modify, or approve `ApprovalRecord` tokens.
* The agent cannot invoke `TrashExecutor` or bypass `PathValidator`.
* The agent has zero access to HMAC keys or signature generation routines.
* Prompt injection defense patterns (`app/agent/policies.py`) are expanded to intercept simulated trend approvals or fake authorization claims.

## 16. Privacy & Data Minimization Architecture

1. **Metadata-First Architecture**: MacGuard inspects directory paths, file sizes, inodes, and modification times. It **never reads or parses user document contents**.
2. **Local-Only Processing**: All analytics, indexing, duplicate hashing, and LLM inference occur strictly on the local machine. Zero network telemetry.
3. **Sensitive Path Redaction**: User home names and sensitive credentials paths (`.ssh`, `.aws`) are masked or sanitized in presentation views where appropriate.

---

## 17. Performance & Resource Bounds

1. **Memory Budget**: Scanner memory footprint bounded to $< 150 \text{ MB}$ regardless of scan size using streaming iterators and bounded top-N heaps (`heapq`).
2. **APFS Fast Metadata**: Uses `os.scandir()` for fast directory walks without statting file contents.
3. **Cancellation & Graceful Timeout**: All long-running scan jobs support cooperative cancellation tokens (`threading.Event`).
4. **On-Demand Deep Analysis**: Duplicate detection and deep developer inspection only run when explicitly triggered by the user.

## 19. Threat Model & Adversarial Analysis (v1.1 Additions)

| Threat Vector | Description | v1.1 Mitigation |
|---|---|---|
| **T26: Symlink Directory Loop DoS** | Circular symlinks causing infinite traversal loops during whole-home scanning. | Maintain set of visited real device/inode tuples; abort recursive follow on symlinks. |
| **T27: Memory Exhaustion via Millions of Files** | Huge user trees exhausting RAM during duplicate detection. | Size pre-filtering; stream hashes via generators; bounded heap containers. |
| **T28: TCC Permission Denied Crash** | Inaccessible macOS privacy locations (e.g. `~/Library/Safari`) causing scan crashes. | Structured `try...except PermissionError` yielding non-fatal warning diagnostics. |
| **T29: Agent Hallucinated Trend Authorization** | Adversarial prompt claiming historical growth grants auto-approval. | Agent policy rejects implicit approvals; safety layer requires physical HMAC token. |
